THE FOUR SQUARESPACE LOCATIONS (don't mix these up)
-----------------------------------------------------
1. Settings -> Advanced -> Code Injection -> HEADER   (site-wide, once)
2. Settings -> Advanced -> Code Injection -> FOOTER    (site-wide, once)
3. Each page's own Code Block, added in the page content area (per page)
4. Each page's own Page Settings -> Advanced -> "Page Header Code
   Injection"                                          (per page, requires
                                                         Business plan or
                                                         higher)


STEP 1 -- Site-wide code (do this once)
-----------------------------------------
a) Settings -> Advanced -> Code Injection -> HEADER field:
   paste the entire contents of squarespace-sitewide/head-injection.txt

b) Settings -> Advanced -> Code Injection -> FOOTER field:
   paste the entire contents of squarespace-sitewide/footer-injection.txt

c) Design -> Custom CSS (or Custom CSS panel), add:
     header:not(#tc-header) { display: none !important; }
     footer:not(#tc-footer) { display: none !important; }
   This hides Squarespace's own template header/footer so only ours shows.
   (If your whole page looks broken after this, it's almost always because
   the header/footer injection from step (a)/(b) didn't save -- re-check
   those two fields before touching this CSS again.)

ABOUT sitemap.xml AND robots.txt
------------------------------------
Squarespace automatically generates and serves its own /sitemap.xml and
/robots.txt for your domain -- most plans don't let you upload a file to
override those exact paths. The sitemap.xml and robots.txt in this
folder are provided as a REFERENCE (the full, correct list of all 18
URLs with their hreflang pairings) -- useful for manually submitting URLs
to Google Search Console, or if the site is ever migrated off
Squarespace. Squarespace's own auto-generated sitemap will pick up these
pages automatically once they're published and out of "don't show in
navigation" limbo is not required for indexing (that setting only
affects the visible menu, not crawlability).

- One inherent limitation of the code-injection approach: the <html
  lang="..."> attribute is set by JavaScript after the page loads
  (matching the page's real language), not by Squarespace itself at the
  server level. This is a minor, known limitation of building bilingual
  pages this way on a platform you don't control the server templating
  of -- if your Squarespace plan ever supports native multi-language
  sites, that would be a more robust long-term fix. It does not stop
  search engines from indexing the correct language via hreflang, which
  is the part that actually matters most for SEO.
